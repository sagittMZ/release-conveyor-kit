# RUBRIC - критерии качества слэш-команды

Человеческая версия рубрика. Слой 1 (`eval.sh` + `expectations.tsv`) проверяет
пункты 1-5 программно; пункты 6-8 - для слоя 2 (LLM-судья, v2) и ручного ревью.

## Структура (слой 1, программно)

1. **Frontmatter.** Есть `---`-фенсы и `description`. Если команда принимает
   аргумент - есть `argument-hint`.
2. **Аргумент и fallback.** Тело использует `$ARGUMENTS`/`$1`; для случая
   «аргумент не задан» есть ветка (спросить или разумный дефолт).
3. **Guard анализатора.** Команда, которая только читает/анализирует, явно
   запрещает себе менять/коммитить («не пиши код», «ничего не меняй», «не
   начинай»).
4. **Привязка к .ai/.** Если у команды есть естественная роль - в теле есть
   УСЛОВНАЯ ссылка на нужный `.ai/`-файл («если есть <файл> - сверься»).
   Мульти-ролевые ссылаются на карту в `PATTERNS.md`.
5. **Гигиена.** Нет em-dash как пунктуации (правило the owner: `--` -> ` - `).

## Поведение (слой 2, LLM-судья, v2)

6. **Результат, а не шаги.** Команда описывает нужный исход и даёт агенту найти
   путь, а не диктует пошагово (паттерн 1 из PATTERNS.md).
7. **Один чёткий выход.** Ответ команды - в заявленном формате/артефакте, без
   лишнего; не расползается за рамки задачи.
8. **Не выходит за роль.** Анализатор не начинает править; команда-планировщик
   не пишет код; команда уважает границы соседних команд (нет дублей).

Шкала слоя 2: 0-5 на кейс (0 - не делает заявленного, 5 - точно и в границах).
