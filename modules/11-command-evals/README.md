# Модуль 11 - command-evals

Измеримое качество слэш-команд модуля 09 вместо оценки «на глаз». Локальный
аналог `eval-driven-agent-development`: рубрик + проверки + базлайн + дельта.
Весь модуль - на текущем стеке (bash + Claude Code), без облака и платных джобов.

## Философия: программное сначала, судья точечно

- **Слой 1 (этот v1, всегда, 0 стоимости):** детерминированные bash-проверки
  исходников команд. Ловит структурные дефекты: битый frontmatter, отсутствие
  fallback у команд с аргументом, потерянную привязку к `.ai/`, пропавший guard
  «не пиши код», em-dash. Регенерируем, годится в CI-гейт.
- **Слой 2 (реализован):** LLM-судья по тест-кейсам для поведенческого качества,
  которое структура не ловит. Субагент исполняет команду на задаче-входе,
  второй субагент-судья оценивает ответ по рубрику (SCORE 0-5 / PASS / NOTES).
  Запуск - внутри уже идущей сессии через `/eval-command --judge`, не отдельным
  платным джобом. Гоняется точечно и по используемым командам.

## Состав

| Файл | Что это |
|---|---|
| RUBRIC.md | Критерии качества команды человеческим языком (для слоя 2 и ревью) |
| expectations.tsv | Рубрик слоя 1 в машинном виде: по строке на команду (needs_arg / analyzer / ai_role) |
| eval.sh | Харнесс слоя 1: проверки + карточка баллов + дельта против базлайна |
| cases/&lt;имя&gt;.md | Тест-кейсы слоя 2 на выдуманных примерах: вход + expect/avoid |
| judge/judge-prompt.md | Промпт LLM-судьи слоя 2 (SCORE/PASS/NOTES) |
| commands/ -> команда /eval-command живёт в modules/09-prompt-library/commands/ (единый дом команд) |

## Запуск

```
bash modules/11-command-evals/eval.sh [--all|<имя>] [--baseline] [--strict]
```

- без аргументов / `--all` - эвалить все команды;
- `<имя>` - одну команду;
- `--baseline` - зафиксировать текущий результат как базлайн для будущих дельт;
- `--strict` - ненулевой код выхода при любой проваленной проверке (для CI).

Из сессии - командой `/eval-command $ARGUMENTS`.

Вывод: карточка в stdout + `docs/evals/scorecard.{md,tsv}`. Базлайн -
`docs/evals/baseline.tsv`. Каталог `docs/evals/` в `.gitignore` (регенерируем,
содержит счётчики использования из приватных транскриптов) - в историю не едет.

## Проверки слоя 1

Универсальные (по каждой команде): валидный frontmatter с `description`; нет
em-dash как пунктуации; ссылка на ролевой `.ai/`-файл (если есть) - условная.
По ожиданиям из `expectations.tsv`: команда с аргументом имеет `argument-hint`,
`$ARGUMENTS`/`$1` и fallback; команда-анализатор имеет guard «не меняй/не
коммить/не начинай»; заявленная роль привязана к нужному `.ai/`-файлу (или к
карте `PATTERNS.md` для мульти-ролевых).

Новая команда без строки в `expectations.tsv` - осознанный FAIL «нет ожиданий»:
добавь строку, объявив намерение.

## Связь с usage-digest

`eval.sh` через `lib-transcripts.sh` (модуль 09) берёт частоты команд и
ранжирует вывод: реально используемые - выше. Команды с нулём использования -
кандидаты на переименование/удаление (та же логика, что в дайджесте).

## Слой 2 - запуск

Из сессии: `/eval-command --judge`. Для каждой команды с файлом `cases/<имя>.md`
агент субагентом исполняет команду на входе кейса, вторым субагентом-судьёй
оценивает ответ по `judge/judge-prompt.md` + `RUBRIC.md` + expect/avoid кейса,
сводит SCORE/PASS/NOTES в `docs/evals/judge-<дата>.md`. Кейсы - на выдуманных
примерах (публикуемость). Гонять точечно (стоимость субагентов) и по реально
используемым командам.
