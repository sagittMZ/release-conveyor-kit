# Usage digest - дайджест использования промптов/команд

Отвечает на вопрос «какие промпты/скиллы реально используются», который
голая библиотека-меню не решает. Меряет вызовы слэш-команд по транскриптам
Claude Code и даёт недельный срез: что реально пошло в дело, а что лежит
мёртвым грузом.

## Как работает

Каждый вызов `/команды` пишется в транскрипт сессии
(`~/.claude/projects/<проект>/*.jsonl`) как `<command-name>/имя`. Скрипт
`usage-digest.sh` за окно в N дней (по умолчанию 7) считает вызовы команд
библиотеки и печатает сводку. Опционально шлёт её в Telegram, если в
окружении заданы `TG_BOT_TOKEN` и `TG_CHAT_ID`.

## Запуск руками

```bash
bash usage-digest.sh                 # отчёт в stdout, окно 7 дней
DIGEST_DAYS=30 bash usage-digest.sh  # окно 30 дней
```

## По расписанию

Дайджест вешается на cron ОТДЕЛЬНОЙ обёрткой вне репозитория - чтобы токен
не попал в git:

```bash
# ~/prompt-usage-digest.sh  (вне репозитория, chmod 600)
#!/bin/bash
export TG_BOT_TOKEN="<токен>"
export TG_CHAT_ID="<chat_id>"
export DIGEST_DAYS=7
KIT=<путь-к-клону-кита>
bash "$KIT/modules/09-prompt-library/usage-digest/usage-digest.sh"
```

```
# crontab: воскресенье
5 16 * * 0 ~/prompt-usage-digest.sh
```

## Как читать дайджест

- **Ноль вызовов у команды за период** - её либо не находят (плохой нейминг,
  не знаешь что она есть), либо не нужна. Кандидат на переименование или
  удаление.
- **Частые вызовы** - кандидат на следующую ступень лестницы закрепления:
  из команды в хук (делать автоматически, без вызова).
- Через 2-4 недели накопится статистика для осознанного набора 1.5-B, а не
  по догадке.

## Ограничение v0

Окно считается по времени модификации файла транскрипта (`find -mtime`), не
по таймстемпам отдельных сообщений внутри. Для недельного дайджеста этого
достаточно; если понадобится точность до сообщения - парсить поле времени в
jsonl.
