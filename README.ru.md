# Release Conveyor Kit

Слэш-команды и проверки, которые заставляют ИИ-агента показывать работу, а не
просто говорить "готово".

[![CI](https://github.com/sagittMZ/release-conveyor-kit/actions/workflows/ci.yml/badge.svg)](https://github.com/sagittMZ/release-conveyor-kit/actions/workflows/ci.yml)

Вы пишете код с ИИ-агентом, а он:

- говорит "протестировано" и "проверено", но показать ему нечего
- забывает всё, как только сессия закончилась
- одну и ту же работу каждый раз делает по-разному
- соглашается с вами вместо того, чтобы возразить

Кит - это набор папок, которые ваш агент копирует в ваш репозиторий. Это не
пакет и не CLI, устанавливать ничего не нужно.

Это перевод [README.md](README.md). Вся остальная документация, команды и
промпты - на английском.

Настоящий запуск `/precommit` на сгенерированном репозитории с тремя
подсаженными дефектами. Как это записано и как повторить:
[docs/demo/](docs/demo/README.md).

## Добавить в свой проект

Для репозитория, который у вас уже есть, на любом языке. Нужны git и
[Claude Code](https://claude.com/claude-code).

1. Клонируйте кит рядом со своим проектом:

   ```bash
   git clone https://github.com/sagittMZ/release-conveyor-kit.git
   ```

2. Откройте сессию агента в **своём** проекте и вставьте промпт раскатки из
   [modules/09-prompt-library/ROLLOUT.md](modules/09-prompt-library/ROLLOUT.md),
   подставив путь к своему клону.
3. Агент скопирует команды, покажет вам дифф и дождётся вашего слова перед
   коммитом. Код приложения он не трогает.
4. Перед следующим коммитом наберите `/precommit`.

Команды - это обычные промпты в Markdown, их прочитает любой агент. Сам кит
написан и запускался в Claude Code.

## Начать новый проект

Кит не генерирует приложение. Новому проекту он даёт обвязку с первого
коммита, и это самый дешёвый момент, чтобы её завести.

1. Создайте репозиторий и сделайте первый коммит:

   ```bash
   mkdir my-project && cd my-project
   git init && git commit --allow-empty -m "Initial commit"
   ```

2. Дальше идите по разделу
   [Добавить в свой проект](#добавить-в-свой-проект) с шага 1.
3. Первую фичу начните с `/spec`, спланируйте через `/impl-plan`, а сессию
   закройте командой `/session-wrap`.

Этот путь один раз пройден на пустом репозитории: 82 файла подготовлены к
коммиту, структурные оценки 62 из 62, каждый скопированный файл со штампом
источника.

## Выпустить MVP

Для приложения на React + Vite + Capacitor + Supabase + Vercel, которое
работает и теперь должно дойти до пользователей. Релизный конвейер добавляет
CI, сборки под Android и iOS, инструкции для сторов, стейджинг, мониторинг,
гигиену секретов и набор смоук-тестов.

1. Сначала добавьте обвязку, как описано выше.
2. Откройте сессию агента в своём проекте и дайте ему промпт из
   [modules/08-agent-layer/](modules/08-agent-layer/). Он задаст вам вопросы,
   определит стек, применит модули по порядку и проверит каждый.
3. Выполните ручные шаги из его итогового отчёта: аккаунты, оплата, секреты и
   кнопки в консолях сторов. Для каждого шага модули дают нумерованную
   инструкцию, а настоящих секретов в репозитории не бывает:
   [modules/06-secrets/](modules/06-secrets/README.md).

На любом другом стеке эта часть неприменима; первые две применимы.

## Команды, с которых вы начнёте

| Команда | Что делает |
|---|---|
| `/spec` | Расспрашивает вас о фиче, потом пишет спецификацию |
| `/impl-plan` | Поэтапный план от команды ролей, до любого кода |
| `/edge-cases` | Состояния ошибок, пустые состояния и крайние случаи для фичи |
| `/precommit` | Ревью незакоммиченных правок: баги, утёкшие секреты, забытые правки |
| `/security-scan` | Ревью безопасности по указанному пути, его делает отдельный агент |
| `/release-notes` | Заметки к релизу между двумя тегами или коммитами, сгруппированные по типу |
| `/session-wrap` | Завершает сессию коротким снимком, с которого начнётся следующая |
| `/handoff` | Пишет стартовый промпт для следующей сессии |

Ещё шесть (`/audit`, `/backlog`, `/scope-triage`, `/eval-command`,
`/consolidate-memory`, `/arch-viz`) и меню из 21 готового промпта по фазам
проекта лежат в [modules/09-prompt-library/](modules/09-prompt-library/).
Разобранные примеры: [docs/prompt-kit-guide.md](docs/prompt-kit-guide.md).

## Что ещё в коробке

| Часть | Что вы получаете | Статус |
|---|---|---|
| Команды и промпты (модуль 09) | Слэш-команды выше и меню промптов | Работает на самом ките |
| Оценки команд (модуль 11) | Оценка для каждой команды, чтобы испортившийся промпт был пойман до того, как навредит | Работает на самом ките |
| Память (модуль 12) | История сессий, сжатая в заметки, которые вы просматриваете | Работает на самом ките |
| Страница архитектуры (модуль 13) | Один HTML-файл с архитектурой вашего проекта, актуальность держит CI. [Пример](docs/arch/index.html) | Работает на самом ките |
| Релизный конвейер (модули 01-08) | CI, сборки под Android и iOS, инструкции для сторов, стейджинг, мониторинг, гигиена секретов, смоук-тесты. Только один стек | Частично извлечён из боевого конвейера, частично не проверен |
| Восстановление сессий (модуль 14) | Сессии агентов и их темы в чате возвращаются после перезагрузки | Проверено частично: настоящий холодный старт вернул все сессии; последнее исправление в холодном старте ещё не запускалось |

## Что не проверено

Кит никогда не выдаёт шаблон, который не запускался, за проверенный. README
каждого модуля делит содержимое на *извлечено из работающего проекта* и
*добавлено китом, не проверено*. Полный список для этого релиза:
[docs/NOT-VERIFIED.md](docs/NOT-VERIFIED.md).
